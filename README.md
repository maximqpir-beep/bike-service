# Велосервис — КР 1

Консольная информационная система: клиенты и заявки на обслуживание велосипедов.
Java 17, Maven, PostgreSQL, JDBC, Apache POI. Интерфейс — на русском языке.

## Возможности

- CRUD клиентов и заявок, получение по ID.
- Поиск заявок по части марки и описания без учёта регистра.
- Фильтры по статусу и типу велосипеда.
- Сортировка по дате создания и стоимости по возрастанию; неизвестная стоимость — в конце.
- Статистика: количество клиентов и заявок, количество по каждому из шести статусов, средняя указанная стоимость, сумма завершённых работ.
- Экспорт актуальных данных из БД в `.xlsx`: листы «Клиенты» и «Заявки».
- Обработка неверного ввода, отсутствующего ID, нарушений правил и ошибок JDBC.

## Что установить

1. **JDK 17** (именно JDK, не только JRE).
2. **Maven 3.9+** или использовать Maven в IntelliJ IDEA.
3. **PostgreSQL**, например 16, и pgAdmin или `psql`.
4. Git либо скачать репозиторий через **Code → Download ZIP**.

Проверьте в терминале `java -version` и `mvn -version`: обе команды должны использовать Java 17.

## Запуск по шагам

### 1. Получить проект

```bash
git clone https://github.com/maximqpir-beep/bike-service.git
cd bike-service
```

В IntelliJ IDEA откройте эту папку как Maven-проект; Project SDK — JDK 17.

### 2. Создать базу и загрузить данные

Через терминал (пароль PostgreSQL вводится по запросу):

```bash
psql -U postgres -c "CREATE DATABASE bike_service;"
psql -U postgres -d bike_service -v ON_ERROR_STOP=1 -f sql/01_schema.sql
psql -U postgres -d bike_service -v ON_ERROR_STOP=1 -f sql/02_seed.sql
```

Или в **pgAdmin**: создайте базу `bike_service`, откройте её **Query Tool**, выполните сначала `sql/01_schema.sql`, затем `sql/02_seed.sql`.
Скрипты рассчитаны на однократный запуск в новой базе. Они не удаляют существующие таблицы.
Начальные данные: **5 клиентов, 12 заявок, 6 статусов**. Все контакты вымышленные.

### 3. Задать подключение

PowerShell (Windows):

```powershell
$env:DB_URL = "jdbc:postgresql://localhost:5432/bike_service"
$env:DB_USER = "postgres"
$env:DB_PASSWORD = "ваш_локальный_пароль"
```

Bash (Linux/macOS):

```bash
export DB_URL='jdbc:postgresql://localhost:5432/bike_service'
export DB_USER='postgres'
read -s -p 'Пароль PostgreSQL: ' DB_PASSWORD
export DB_PASSWORD
```

В IntelliJ IDEA: **Run → Edit Configurations → Main → Environment variables**. Добавьте те же три переменные. `.env` автоматически не читается.
Не добавляйте пароль в исходники и коммиты.

### 4. Собрать и запустить

В том же терминале, где заданы переменные:

```bash
mvn clean verify
java -jar target/bike-service-1.0.0.jar
```

Или запустите `ru.mirea.bikeservice.Main` в IntelliJ IDEA.
Меню работает до выбора `0`. После операции или обработанной ошибки возвращается в главное меню.
При изменении записи все редактируемые поля вводятся заново; статус заявки меняется отдельным пунктом.

### 5. Сделать Excel для защиты

Выберите **7. Экспорт Excel**. Файл появится в `exports/bike-service-ДАТА-ВРЕМЯ.xlsx` относительно рабочей папки.
В нём будут данные из вашей БД на момент экспорта. Файлы экспорта не включаются в Git, чтобы не публиковать реальные контакты клиентов.
[Учебный пример экспорта из PostgreSQL](examples/service-requests.xlsx) находится в `examples/`.

## Архитектура и ООП

```text
ConsoleApplication → Service → Repository (интерфейсы) → JDBC → PostgreSQL
```

| Пакет | Назначение |
|---|---|
| `model` | Client, ServiceRequest, RequestStatus, BikeType; private-поля и методы доступа |
| `ui` | Консольное меню, ввод и вывод; здесь нет SQL |
| `service` | Бизнес-правила, поиск, фильтры, сортировка и статистика |
| `repository` | Общий контракт CrudRepository и интерфейсы сущностей |
| `repository.jdbc` | JDBC-реализации, SQL и преобразование ResultSet в объекты |
| `exception` | Собственные исключения |
| `util` | Подключение к БД, чтение ввода, экспорт Excel |

Полиморфизм: `ClientRepository clients = new JdbcClientRepository(db);`.
Общий абстрактный `JdbcRepository<T>` реализует повторяющиеся CRUD-операции; подклассы задают отображение полей.
Имена таблиц и колонок берутся только из кода подклассов. Пользовательские значения передаются через параметры `?`.
Поиск, фильтрация и сортировка выполняются Stream API над списком из БД — это допустимо для учебного объёма данных.

## Бизнес-правила

1. Клиент заявки должен существовать.
2. ФИО, телефон клиента, марка и описание неисправности обязательны; длины ограничены.
3. Телефон: 10–15 цифр, разрешён начальный `+`; пробелы, скобки и дефисы нормализуются.
4. Телефон и непустой email уникальны; email проверяется на базовый формат.
5. Тип велосипеда обязателен и задан enum.
6. Стоимость — от 0 до 99999999.99 и не более двух десятичных знаков; до завершения может быть неизвестна.
7. Новая заявка всегда имеет статус CREATED и текущую дату создания.
8. Статус меняется только по разрешённым переходам (таблица ниже).
9. Для завершения нужна указанная стоимость; дата завершения устанавливается автоматически.
10. Завершённые и отменённые заявки нельзя редактировать или переводить в другой статус.
11. Клиента с заявками нельзя удалить. Сначала удалите его заявки, если это действительно требуется.

Удаление самой заявки разрешено и требует подтверждения в меню.
Обычное редактирование заявки не меняет её статус и даты, поэтому не позволяет обойти проверку переходов.

| Из статуса | В статус |
|---|---|
| CREATED | ACCEPTED, CANCELLED |
| ACCEPTED | IN_PROGRESS, CANCELLED |
| IN_PROGRESS | WAITING_FOR_PARTS, COMPLETED, CANCELLED |
| WAITING_FOR_PARTS | IN_PROGRESS, CANCELLED |
| COMPLETED, CANCELLED | Переходов нет |

## Проверки

`mvn test` выполняет тесты на H2 в режиме совместимости с PostgreSQL. Это быстрая проверка JDBC и правил, а не замена проверки на PostgreSQL.
Для тех же тестов на настоящем PostgreSQL задайте:

```bash
export TEST_DB_URL='jdbc:postgresql://localhost:5432/bike_service'
export TEST_DB_USER='postgres'
export TEST_DB_PASSWORD="$DB_PASSWORD"
mvn test
```

Тесты создают уникальную схему `test_...` для каждого сценария и удаляют только её; пользователь тестирования должен иметь право создавать схемы. Рабочие таблицы в `public` не изменяются.
В PowerShell задавайте эти переменные через `$env:ИМЯ = "значение"`.

## Ограничения учебной версии

Нет авторизации, аудита и защиты от одновременного редактирования одной заявки несколькими экземплярами программы. Проверки сервиса и запись не объединены в одну транзакцию; ограничения БД защищают связи и уникальность, но версия рассчитана на одного оператора. Для больших объёмов поиск и агрегации следует перенести в SQL с пагинацией. Эти ограничения можно обсудить при переходе к REST API.
