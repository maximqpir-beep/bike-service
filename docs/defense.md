# Подготовка к защите: ООП, SQL и JDBC

Это вероятные вопросы по требованиям задания, а не известный заранее список преподавателя. Объясняйте каждый ответ на конкретном месте в коде.

## Рассказ на одну минуту

«Наша система ведёт клиентов велосервиса и заявки на ремонт велосипедов. Один клиент может иметь несколько заявок. Данные хранятся в PostgreSQL. Консольный интерфейс вызывает сервис, сервис проверяет бизнес-правила, а репозитории работают с базой через JDBC. Реализованы создание, просмотр, изменение, удаление, поиск, фильтрация, сортировка, статистика и экспорт в Excel. Например, нельзя создать заявку для несуществующего клиента и нельзя завершить новую заявку, минуя принятие и ремонт».

## ООП — организация Java-кода

**Что такое класс и объект?**
Класс описывает поля и поведение, объект — конкретный экземпляр. `Client` — класс, а `new Client(...)` — объект конкретного клиента. Строка таблицы и объект связаны данными, но это разные вещи: строка хранится в БД, объект существует в памяти Java.

**Какие принципы ООП применены?**
Инкапсуляция — private-поля моделей; абстракция — контракт `CrudRepository<T>`; наследование — JDBC-репозитории наследуют общий `JdbcRepository<T>`; полиморфизм — сервис использует интерфейс, а во время выполнения вызывается метод JDBC-реализации.

**Зачем private, если есть setter?**
Прямой доступ к полю запрещён, доступ предоставлен через методы. Но наличие setter само по себе не гарантирует корректность. В этой версии модели являются контейнерами данных, а полноценные бизнес-проверки сосредоточены в сервисе. В дальнейшем можно сделать модели более строгими или неизменяемыми.

**Чем интерфейс отличается от класса?**
Интерфейс задаёт контракт операций. Обычный класс можно создать через `new`; интерфейс непосредственно создать нельзя. Интерфейс в Java может содержать default/static-методы, поэтому формулировка «в интерфейсе никогда нет реализации» неверна.

**Покажите полиморфизм.**
В `Main.java`: `ClientRepository clients = new JdbcClientRepository(db);`. Тип переменной — интерфейс, реальный объект — JDBC-класс. Вызов `clients.findAll()` выполняет реализацию реального объекта. Сервису не нужно знать SQL.

**Зачем абстрактный JdbcRepository?**
Чтобы не повторять save/findAll/findById/update/delete в двух классах. Подклассы реализуют `map`, `bind`, `id`, `setId`. Абстрактный класс нельзя создать напрямую; он может содержать поля, конструктор и готовые методы.

**Что такое enum?**
Тип с фиксированным набором значений. `RequestStatus` не позволяет передать произвольную строку как статус в Java. При этом enum сам не запрещает переход CREATED → COMPLETED: это проверяет сервис. В БД допустимые значения дополнительно ограничивает CHECK.

**Зачем BigDecimal?**
Для точных десятичных расчётов стоимости. `double` хранит двоичные приближения. Создаём BigDecimal из строки, сравниваем через `compareTo`, для среднего явно задаём округление `HALF_UP`. В Excel числовая ячейка хранит число в формате Excel, поэтому при экспорте используется `doubleValue()`; расчёты приложения остаются в BigDecimal.

**Где коллекции и Stream API?**
`List<ServiceRequest>` возвращается репозиторием. `filter` выбирает элементы, `sorted` сортирует, `count` считает, `reduce` суммирует. Эти операции не изменяют записи в БД. В учебной версии сначала загружается список, затем обрабатывается в Java.

**Что делает Optional?**
Обозначает, что запись может отсутствовать. Репозиторий возвращает `Optional.empty()`, сервис превращает отсутствие в `EntityNotFoundException` с понятным сообщением.

## SQL — работа с данными

**Чем SQL отличается от PostgreSQL и JDBC?**
SQL — язык запросов. PostgreSQL — СУБД, которая хранит данные и исполняет запросы. JDBC — Java API для общения с СУБД через драйвер.

**Какие таблицы и связь?**
`clients` и `service_requests`. Связь один-ко-многим через `service_requests.client_id → clients.id`. Сам внешний ключ не создаёт клиента, а проверяет, что он существует.

**PRIMARY KEY, FOREIGN KEY, UNIQUE, NOT NULL, CHECK?**
PRIMARY KEY однозначно определяет строку и не допускает NULL. FOREIGN KEY обеспечивает ссылочную целостность. UNIQUE запрещает дубликаты значений. NOT NULL требует наличие значения. CHECK проверяет выражение, например неотрицательную стоимость.

**Что такое NULL?**
Отсутствие значения, не ноль и не пустая строка. Неизвестная стоимость — NULL; бесплатная работа — 0. Для проверки используется `IS NULL`, а не `= NULL`. В PostgreSQL обычный UNIQUE допускает несколько NULL, поэтому email необязателен.

**Что такое CRUD?**
Create → INSERT, Read → SELECT, Update → UPDATE, Delete → DELETE.

```sql
SELECT * FROM service_requests WHERE id = 1;
SELECT * FROM service_requests WHERE status = 'IN_PROGRESS';
SELECT * FROM service_requests ORDER BY estimated_cost ASC NULLS LAST;
SELECT status, COUNT(*) FROM service_requests GROUP BY status;
SELECT r.id, c.full_name, r.bike_brand
FROM service_requests r JOIN clients c ON c.id = r.client_id;
```

**Для чего JOIN?**
Чтобы получить данные из связанных таблиц одним запросом. Последний пример соединяет заявку с именем клиента. В нашем Excel имена присоединяются в Java через Map, поэтому не нужно утверждать, что в экспортёре используется SQL JOIN.

**Чем WHERE отличается от HAVING?**
WHERE отбирает строки до группировки, HAVING — группы после GROUP BY. Например `GROUP BY status HAVING COUNT(*) > 2`.

**Почему нельзя удалить клиента с заявками?**
Это создало бы заявки без владельца. Сервис даёт понятное сообщение, а FK с ON DELETE RESTRICT защищает БД даже при прямом SQL.

**Зачем индекс?**
Может ускорить поиск и соединение, но занимает место и добавляет работу при записи. Есть индексы на client_id и status. Поиск Stream API в данной версии их непосредственно не использует.

**Что такое транзакция?**
Группа операций, которые фиксируются через COMMIT или отменяются через ROLLBACK. SQL-скрипты создания и заполнения обёрнуты в транзакции. Обычные JDBC CRUD-операции используют autoCommit: каждое выражение фиксируется отдельно. Между проверкой сервиса и записью нет общей транзакции — это ограничение версии с одним оператором.

## JDBC — связь Java с PostgreSQL

**Что происходит при создании заявки?**
Меню читает данные → сервис проверяет поля и клиента, задаёт CREATED и дату → репозиторий открывает Connection → создаёт PreparedStatement → передаёт параметры → executeUpdate выполняет INSERT → getGeneratedKeys возвращает ID → ресурсы закрываются.

**Зачем драйвер PostgreSQL?**
JDBC — общий API. Драйвер реализует взаимодействие с конкретной СУБД по её протоколу. Maven подключает `org.postgresql:postgresql`; современный JDBC находит драйвер автоматически.

**Что такое Connection?**
Соединение с базой данных. В проекте его создаёт DatabaseManager через DriverManager.getConnection(url, user, password).

**Statement и PreparedStatement — в чём разница?**
Statement выполняет SQL-строку. PreparedStatement позволяет передать значения отдельно через `?` и `setString`, `setLong`, `setBigDecimal`. Опасна конкатенация пользовательского ввода в SQL. Statement сам по себе не является уязвимостью, если запрос — фиксированная строка без пользовательских данных.

```java
String sql = "SELECT * FROM clients WHERE id = ?";
try (Connection c = db.getConnection();
     PreparedStatement ps = c.prepareStatement(sql)) {
    ps.setLong(1, id);
    try (ResultSet rs = ps.executeQuery()) {
        while (rs.next()) {
            System.out.println(rs.getString("full_name"));
        }
    }
}
```

**Почему параметры нумеруются с 1?**
Так определён JDBC API: первый знак `?` имеет индекс 1.

**Можно ли через ? передать имя таблицы?**
Нет, параметры предназначены для значений. Имена таблиц в нашем общем репозитории берутся из фиксированных строк в коде подклассов, а не от пользователя.

**executeQuery и executeUpdate?**
executeQuery возвращает ResultSet для SELECT. executeUpdate используется для INSERT/UPDATE/DELETE и возвращает количество затронутых строк. Это помогает понять, найдена ли строка при изменении или удалении.

**Что такое ResultSet и зачем next()?**
Результат запроса с курсором. Сначала курсор стоит перед первой строкой. `next()` сдвигает его к следующей строке и возвращает true, если она есть. `map` читает значения и создаёт объект модели.

**Что даёт try-with-resources?**
Автоматически закрывает Connection, PreparedStatement и ResultSet, в том числе при исключениях. Ресурсы закрываются в обратном порядке объявления. Это предотвращает утечки соединений.

**Как обрабатываются ошибки?**
Репозиторий ловит SQLException и оборачивает его в DatabaseException, сохраняя причину. Сервис бросает BusinessException или EntityNotFoundException. Меню выводит сообщение и продолжает цикл. Неверное число обрабатывает InputReader. Проверки ввода не заменяют бизнес-проверки сервиса.
