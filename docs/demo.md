# Демонстрация на 5–7 минут

Подготовьте PostgreSQL, начальные данные, терминал с приложением, редактор кода и Excel/LibreOffice.

1. **Модель и таблицы.** Покажите ER-диаграмму и пункт 8: пять клиентов, двенадцать заявок. Объясните связь один-ко-многим.
2. **Создание.** Через меню клиентов добавьте учебного клиента с уникальным телефоном, запомните ID. Создайте для него заявку: Trek, Marlin, MOUNTAIN, «Скрип тормозов», 1500.
3. **CRUD.** Найдите заявку по полученному ID, измените описание и стоимость. Поля при изменении вводятся заново. Покажите, что запись сохраняется после перезапуска приложения.
4. **Статусы.** Попытайтесь завершить CREATED — получите отказ. Затем выполните ACCEPTED → IN_PROGRESS → WAITING_FOR_PARTS → IN_PROGRESS → COMPLETED. Покажите дату завершения. Возврат в работу запрещён.
5. **Поиск и анализ.** Поиск «trek», поиск «скрип», фильтры по статусу и типу, сортировки по стоимости и дате, статистика.
6. **Ошибки.** Введите `abc` вместо ID; найдите отсутствующий ID; создайте заявку с отрицательной стоимостью; попробуйте удалить клиента с заявками. Программа продолжает работать.
7. **Excel.** Выберите пункт 7, откройте созданный файл: два листа, реальные строки БД, числовая стоимость, даты, автофильтры.
8. **Удаление.** Удалите только добавленную для показа заявку, подтвердив «да», затем её клиента. Начальные данные сохраняются.

Перед защитой выполните сценарий самостоятельно. Не изменяйте начальные заявки наугад: иначе ожидаемые количества в примерах перестанут совпадать.
